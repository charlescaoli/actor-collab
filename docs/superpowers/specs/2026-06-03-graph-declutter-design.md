# 关系图减负 + 动感改造设计

日期：2026-06-03
范围：`js/graph.js`（`ForceGraph` 类）单文件改动

## 背景与问题

合作关系图当前信息密度过高，用户反馈"乱"。具体噪点（用户确认）：

1. **每个节点常驻文字** —— 桌面端每个节点头像下都画「名字（6 字）+ N 次」两行，30 个节点 = 60 段文字，互相叠压。
2. **画布内的悬浮卡** —— hover/选中时在 canvas 上画一张卡片（名字 + 合作次数 + 2 部共同作品），与下方已有的详情面板（`graphDetail`）信息重复。
3. **连线/边** —— 中心到每个节点的边用粗细/亮度编码合作次数；30 条叠加起来是噪点。

用户**不认为节点数量（30）是问题**，因此不减少节点。

用户选定方向：**方案 B（聚焦模式）+ 动感（入场弹出 + 持续轻漂）**。

## 当前行为（改造前）

`js/graph.js` 中 `ForceGraph`：

- **桌面**：力导向模拟跑 120 帧后**冻结静止**；每个节点常驻 name+count 标签；hover/选中画悬浮卡；边的 `lineWidth`/`alpha` 由合作次数编码；选中时其余节点压暗。
- **手机**：仅 12 个节点；持续浮动（`updateFloatingPosition`）+ 边脉动；标签和悬浮卡都被 `if (!this.isMobile)` 关掉。
- 节点半径由 `getGraphMetrics(count, maxCount)` 按合作次数缩放（此编码**保留**）。

## 设计（改造后）

全部改在 `js/graph.js`。下方详情面板 `graphDetail`（在 `app.js`）已展示选中节点的名字/次数/共同作品，去掉画布悬浮卡后由它承担详情，无需改 `app.js`。

### 1. 标签按需显示
- 去掉每个节点常驻的 name + count 标签。
- 仅当节点为 **hovered 或 selected** 时，在节点下方显示「名字（≤8 字）+ 合作 N 次」。
- **选中节点的标签常驻**（它是当前焦点），即使鼠标移开也保留，直到切换选中。
- 桌面、手机统一此行为（手机靠点击选中来显示标签）。

### 2. 去除画布悬浮卡
- 删除 `drawNode` 中绘制 tooltip 卡片的整段逻辑。
- 选中节点的详情完全由下方 `graphDetail` 面板呈现。

### 3. 边压淡（去掉次数编码）
- 所有非选中边：统一极淡细线，`rgba(255,255,255,0.07)`，`lineWidth ≈ 0.7`。
- 仅「中心 → 选中节点」那条边高亮：金色 `rgba(245,197,24,0.65)`，`lineWidth ≈ 2`。
- 边不再编码合作次数——该信号由**节点半径**独自承担（`getGraphMetrics` 保留），无信息损失。

### 4. 选中聚焦
- 当存在选中节点时，其余节点整体压暗（`globalAlpha ≈ 0.45`）。
- 选中/hover 节点正常亮度 + 金色描边微光。

### 5. 入场动画（替换"直接出现"）
- 打开关系图时，所有节点初始化在**中心附近**（小幅随机抖动）。
- 力导向模拟启动：节点间斥力把它们"砰"地推散开，向心力**逐帧增强**（从 ~0.010 ramp 到 ~0.022），形成轻微过冲再收拢的弹散感。
- 运行约 150 帧到位，随后将每个节点当前坐标存为浮动基准点 `baseX/baseY`，进入持续轻漂阶段。
- 增加**软性轨道上限**：节点超出 `min(w,h) * 0.42` 时施加回拉力，避免贴墙堆积（实测必要）。

### 6. 持续轻漂（桌面也启用）
- 到位后进入**永久浮动**：每个节点绕 `baseX/baseY` 做 `sin/cos` 轻微漂移（幅度 ~3.5–6px，按合作次数略放大）。
- **选中节点漂幅略大**（~1.4×）以强化存在感。
- 拖拽某节点时，实时更新其 `baseX/baseY`，松手后在新位置继续漂浮。
- 复用并统一现有手机端浮动逻辑（`updateFloatingPosition` 思路），桌面/手机共用一套。

### 7. 「当前选中」面板增强（graphDetail）
去掉画布悬浮卡后，下方 `graphDetail` 面板承接全部详情，并在现有纯文字基础上增强：

- **演员照片**：面板顶部加圆形头像（`node.profile_path` → `profileUrl`），与名字 + 「与 X 合作 N 次」并排。无头像时回退为占位（🎬/首字），与应用其它处一致。
- **共同作品改为海报卡**：把现有 `graph-work-chip` 文字 chip 换成一排海报卡（海报 + 片名 + 年份 + **票房**），横向滚动。海报来自 `work.poster_path` → `posterUrl`，无海报回退占位。
- **海报可点击**：每张卡带 `data-movie-type` / `data-movie-id`，复用已有的全局点击委托 → 打开电影 modal。零额外接线。
- **票房按需拉取**：合作作品对象不含 revenue。选中节点时，对其中的**电影**作品调用 `getMovieDetails`（带缓存）补 revenue，用 `fmtMoney` 显示（如 `$159M`）；**剧集无票房**，仅显示年份。先即时渲染海报+片名+年份，票房到位后回填。
- **防竞态**：选中切换很快，票房回填需校验"该节点仍为当前选中"再写 DOM（沿用 `selectGen` 式的 token，或比对当前选中节点）。

## 手机端适配（全面适配）

手机端（`max-width: 600px`，`isMobile`）有独立的布局与约束，须显式处理，不能套用桌面逻辑：

- **布局**：保留现有 **12 节点环形布局**（`getMobileOrbitPosition`），不跑力导向（小屏力导向会拥挤/溢出）。
- **入场动画**：桌面是力导向爆散；**手机改为"缩放/淡入到环位"**——节点从中心以 ~0.5s 缓动放大 + 淡入到各自环形槽位，保留"弹出"感但不依赖力导向。
- **持续轻漂**：保留手机现有的环形基准点浮动（`updateFloatingPosition`），统一代码路径但**桌面浮动基准 = 力导向落点，手机 = 环位**。
- **标签**：手机无 hover，标签**仅对点选（tap）的节点显示**，且选中标签常驻；与桌面"hover/选中显示"在移动端退化为"仅点选"。
- **边 / 选中聚焦**：与桌面一致（淡边、选中金线、非选中压暗）。
- **画布悬浮卡**：手机本就关闭，维持关闭。
- **「当前选中」面板（§7）在手机上**：面板是 `position:fixed` 的**底部抽屉**（`max-height:38vh`，带拖动条）。增强后须保证抽屉内放得下——头像 + 名字行紧凑、共同作品海报卡复用现有**横向滚动**且**手机用更小海报尺寸**、跳转按钮维持整行宽。实现时在手机宽度下实测高度，必要时压缩海报卡。
- **触屏交互**：点选可用（触屏合成 click）；**拖拽 / 滚轮缩放维持现状只在鼠标下可用**，手机不新增（非倒退）。

## 受影响文件

- `js/graph.js` —— 关系图渲染主体：`initNodes` / `simulate`（拆分为入场 + 浮动两阶段；**桌面力导向爆散、手机环位缩放入场**两条路径）/ `draw` / `drawNode` / 边绘制。
- `js/app.js` —— `renderGraphDetail` 增强（演员头像、海报卡、票房按需拉取 + 防竞态）；新增一个有上限的电影详情缓存（沿用 `cachePut`）。
- `css/style.css` —— `graphDetail` 面板新增头像与海报卡的样式（参照现有 `.collab-card` / `.top-movie-item` 风格）。

## 性能与生命周期

- 持续浮动是永久 `requestAnimationFrame` 循环；必须确保 `destroy()` 调用 `cancelAnimationFrame`（现有 `destroy()` 已处理 `_raf`，改造需沿用单一 `_raf` 句柄）。
- 30 个节点的浮动 + 重绘开销很低；关系图关闭即 `destroy()`，不留后台循环。

## 非目标（明确不做）

- 不减少节点数量（保留桌面 30 / 手机 12）。
- 不改列表视图。
- 不做"选中焦点脉动"动效（用户未选）。
- 不做"边上能量流动/光点"动效（用户未选）。
- 剧集不显示票房（数据源无此字段）。
- **不处理 `prefers-reduced-motion`**（本轮明确不做；入场 + 持续漂浮对所有用户一律生效）。
- 手机端不新增触屏拖拽 / 缩放（维持现状的鼠标-only）。

## 可调参数（实现时按手感微调）

| 参数 | 建议初值 |
|---|---|
| 入场帧数 | ~150 |
| 向心力 ramp | 0.010 → 0.022 |
| 斥力常数 | ~260 |
| 阻尼 | ~0.86 |
| 软轨道上限 | `min(w,h) * 0.42` |
| 浮动幅度 | 3.5 + ratio×2.5 px |
| 选中浮幅倍数 | 1.4× |
| 非选中压暗 alpha | 0.45 |
| 淡边 | `rgba(255,255,255,0.07)`, w≈0.7 |
| 选中边 | `rgba(245,197,24,0.65)`, w≈2 |
